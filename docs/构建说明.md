# 构建与发布说明

## 环境

- Java 语言，最低 Android 4.3（API 18），targetSdk 28，compileSdk 28。
- Android Gradle Plugin 4.2.2、Gradle 6.9.4、JDK 11、Android Build Tools 30.0.3。
- Gradle 和 Maven 下载使用腾讯云、阿里云国内镜像。
- Gradle 6.9.4 是规范中 6.7.1 的同系列维护版本，沿用本机已有完整安装；未改变应用的 Android 兼容级别。
- 界面仅使用 Android 原生 Framework；无 Kotlin、AndroidX、NDK、JNI 或第三方运行时依赖。
- 项目代码量无需 MultiDex，不使用需要核心库脱糖的新 Java API，因此省去规范示例中的 support、MultiDex 和 coreLibraryDesugaring 依赖。Java 8 语法由 Android 构建工具处理。

## 一键构建

在项目根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File tools/build-release.ps1
```

脚本会寻找 `JAVA_HOME` 和 `ANDROID_HOME`，并兼容当前电脑的 `D:\Java\jdk-11.0.1`、`D:\Android\Sdk`。也可明确传入环境路径：

```powershell
powershell -ExecutionPolicy Bypass -File tools/build-release.ps1 -JdkPath D:\Java\jdk-11.0.1 -SdkPath D:\Android\Sdk
```

默认依次执行 `testReleaseUnitTest`、`lintRelease`、`assembleRelease`，只生成 release APK。已有完整 Gradle 缓存时可增加 `-Offline`；只需要重复打包且已验证同一份代码时可使用 `-SkipChecks`。

JVM 临时目录、签名文件保存在 `E:\temp\TVMinesweeper`。Gradle 下载缓存沿用用户的 `.gradle` 目录；Android 构建中间产物位于标准的 `app/build` 目录，均不提交版本库。

产物自动复制到：

```text
release/TVMinesweeper-release-主版本.次版本.修订号.apk
```

项目没有任何 `.so` 库，所以 APK 不需要按 ABI 拆分；交付的单个纯 Java APK 可以直接在 arm64 电视或盒子上安装，没有额外生成 x86 / arm32 原生库。

## 版本与签名

`version.properties` 保存版本号。每次执行 `assembleRelease` 或 `bundleRelease`，构建配置自动增加版本代码和版本修订号，首次发布为 `1.0.0`。构建失败也保留已分配版本，允许版本号跳过，避免对不同二进制产物复用同一版本。源码修改后使用一键构建命令即可获得新文件名。

首次运行构建脚本时，自动生成专用于本项目的 RSA 2048 release 签名密钥和随机密码。默认文件为：

```text
E:\temp\TVMinesweeper\release.keystore
E:\temp\TVMinesweeper\signing.properties
```

请自行备份这两个私有文件，后续版本使用相同密钥才能覆盖安装；清理临时目录前必须保留备份。这些文件不会加入 Git。已有发布证书时，将环境变量 `TVMINESWEEPER_SIGNING_PROPERTIES` 指向自己的配置文件即可：

```properties
storeFile=E:/private/TVMinesweeper.keystore
storePassword=填写自己的密码
keyAlias=填写自己的别名
keyPassword=填写自己的密码
```

release 构建启用 R8 / ProGuard 代码压缩与资源压缩，同时开启 v1、v2 签名，兼顾 API 18 和较新设备。混淆规则保留棋盘 View 构造函数、游戏核心、双击检测和对话框类，并移除调试日志。

## 安装与验收

设备已连接 ADB 时：

```powershell
adb devices
adb install -r release/TVMinesweeper-release-1.0.0.apk
adb shell am start -n com.bigsinger.tvminesweeper/.ui.GameActivity
```

安装命令中的版本应替换为 `version.properties` 的当前值。如果有多个设备，请为 ADB 命令增加 `-s 设备序列号`。

测试报告位于 `app/build/reports/tests/testReleaseUnitTest/index.html`，Lint 报告位于 `app/build/reports/lint-results-release.html`。提交前要求游戏、积分校验、双击检测和按键路由测试通过、Lint 没有 Error，并在雷电模拟器检查遥控器交互；实体电视的 Menu 键映射仍需按具体遥控器验证。音量键由系统处理。

## 版本库约定

使用当前 Git 仓库的唯一主分支，不创建其他分支。源码、中文文档、Gradle Wrapper、图标和 release APK 一并维护；忽略本机配置、私有签名和构建缓存。所有 Markdown 文件使用 UTF-8 和 LF，`.gitattributes` 已固定换行规则。

本项目的图标与 TV 启动器横幅为本地绘制的 PNG，源脚本为 `tools/generate-artwork.ps1`，无需下载外部素材。

## 自动遥控器回归

先安装最新版 APK，使用中文系统的模拟器运行：

```powershell
powershell -ExecutionPolicy Bypass -File tools/verify-device.ps1
```

多设备时增加 `-Serial emulator-5554`（按实际序列号替换）；找不到 ADB 时增加 `-AdbPath D:\Android\platform-tools\adb.exe`。脚本默认保留排行榜和设置，但会重开当前对局，因此应在专用测试设备执行。只有显式传入 `-ResetData` 才会执行 `pm clear` 清除本应用全部数据。

脚本从 UI Automator 无障碍 XML 读取中文棋盘状态，不截图、不修改分辨率。检查边界、OK 单击插旗和双击翻开、长按去重、音量键不改变棋盘、菜单取消和暂停、三种难度尺寸及随机雷数范围、首开安全、后台暂停与恢复、进程重新启动存档。音量测试先读取原媒体音量，测试后恢复原值；无法读取时跳过设备音量操作。运行结束恢复初级空白新局并退出弹窗；失败返回退出码 1。

双击通过同一次设备 shell 的 `input keyevent 23 23` 发出，避免两次 ADB 往返导致时间超窗。弹窗可能遮挡底层无障碍节点，菜单暂停采用停留前后用时差验证。文本报告与 XML 临时文件全部保存在 `E:\temp\TVMinesweeper`。
